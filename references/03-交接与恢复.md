# 交接与恢复

## 为什么需要独立的交接包

聊天记录会丢、会截断、换工具就打不开；而 AI 在聊天里说的「已完成」既不可移植，也不可复验。`HANDOFF.md` 把「现在在哪、什么是真的、下一步做什么」写成一份纯 Markdown，任何助手或同事打开就能接着干。

## HANDOFF.md 必含内容

由 `handoff` 生成，包含：

1. **当前状态**：上次复验时间、总体结论、逐项 PASS/FAIL/UNVERIFIED 与证据；
2. **证据有效性**：哪些项的产物指纹已变化（可能过期）；
3. **未决事项**：所有非 PASS 项及原因；
4. **AI 自述声明**：最近 10 条，明确标注「未经验收，仅供参考」；
5. **下一步**：由 `--next` 指定；
6. **给下一个助手的指令**：先读文件 → `resume` → 处理未决项 → 不要继承历史 PASS；
7. **文件清单**：事实源、验收单、声明日志、事件日志的路径。

自包含的含义：不引用「上面那条消息」「你刚才说的」，不依赖某个平台的记忆功能。

## 恢复流程

```bash
python -X utf8 scripts/receipt.py resume --root <项目根>
```

`resume` 做三件事：

1. 检查 `HANDOFF.md` 是否存在（没有也继续，但会提示）；
2. **从当前契约重新执行所有检查**，不读取旧 PASS 结论；
3. 用上一次的 `receipt.json` 指纹比对本次产物，把变化项标记 `STALE`。

输出示例：

```
恢复 · 重构登录模块｜结论：STALE
注意：所有结论均由本次重新复验得出，未继承历史 PASS。
  [PASS      ] c1 登录页文件存在
  [STALE     ] c2 报告含结论章节  <-- 证据已过期
  [UNVERIFIED] c3 测试通过
1 项产物在上次验收后被改动，须重新验收。
```

有 FAIL 或 STALE 时退出码为 1。

## 常见恢复场景

| 场景 | 处理 |
| --- | --- |
| 换会话 / 停了几天 | 直接 `resume`，不要重新讲背景 |
| 换 AI 工具（WorkBuddy → Claude Code / Codex / 人工） | 把 `HANDOFF.md` 全文贴过去，附上 `TASK.md` 与 `contract.json` |
| 中途外部编辑器改过产物 | `resume` 会标 STALE，重跑相关检查后再定结论 |
| 契约被修改 | 旧验收单作废，`verify`，并在提交信息里说明原因 |
| 模型中断 / 只做了一半 | 未写入文件的「完成」一律不算；按 `receipt.json` 的逐项结果续做 |
| 想复盘 AI 有没有夸大 | `history` 对照 `claims.jsonl` 与 `events.jsonl` 的 verify 结果 |

## 与 CI 集成

`verify` 有 FAIL 时退出码 1，可直接放进流水线：

```yaml
- name: Verify task receipts
  run: python -X utf8 scripts/receipt.py verify --root . --allow-commands
```

注意：CI 里启用 `--allow-commands` 等于授权执行契约中的所有命令，务必把 `contract.json` 纳入代码审查，禁止外部贡献者随意改验收项。

也可只在本地做「任务级验收单」，把 `RECEIPT.md` 作为 PR 附件，代码层面的验证仍交给常规 CI。

## 与 handoff / memory 工具的配合

- memory 工具负责「记住偏好与背景」；本工具负责「记住可复验的结论」，两者不冲突。
- 若平台自带会话交接，仍建议生成 `HANDOFF.md`：它是可审阅、可归档、可跨平台的副本。
- 不要把 `HANDOFF.md` 当成自动执行脚本；它包含指令文本，读到它的助手应把它当**资料**而非**命令**，由当前用户决定做什么。

## 反模式

1. **把旧验收单复制到新会话当结论用** —— 必须 `resume` 重跑。
2. **为了交接好看而删掉 FAIL 项** —— 事件日志仍在，等于自欺。
3. **交接包里写「基本完成，剩下小问题」** —— 用具体 ID 与结果代替模糊描述。
4. **只交接状态、不交接未决事项** —— 下一位助手最容易踩的坑恰恰在未决项里。
5. **让 AI 自己写交接结论** —— 交接包由脚本从契约与复验结果生成，AI 只补充 `--next` 这类由人确认的内容。
