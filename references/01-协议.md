# 协议规范

## 事实源与派生视图

| 文件 | 角色 | 可否重建 |
| --- | --- | --- |
| `.receipt/contract.json` | **唯一事实源**：验收契约 | 否，由人确认 |
| `.receipt/claims.jsonl` | append-only 自述声明 | 否，审计留痕 |
| `.receipt/events.jsonl` | append-only 事件日志 | 否，审计留痕 |
| `TASK.md` | 契约的人可读镜像 | 是 |
| `.receipt/receipt.json` | 最近一次复验结果 | 是 |
| `RECEIPT.md` | 验收单（人读） | 是 |
| `HANDOFF.md` | 交接包（人读） | 是 |

冲突时一律以「重新执行 `verify`」为准，不参考任何缓存或旧结论。派生文件可以整批删除后重建，不影响审计日志。

## 契约结构

```json
{
  "format_version": 1,
  "title": "重构登录模块",
  "created": "2026-11-11 23:10:00",
  "items": [
    {
      "id": "c1",
      "claim": "登录页文件存在",
      "required": true,
      "check": { "type": "file_exists", "path": "src/login.py" }
    }
  ]
}
```

- `id`：项目内唯一，建议 `c1`、`c2`…；重复 id 会被 `add` 拒绝。
- `claim`：一句自然语言承诺，写给**人**看，必须能用后面的检查项判定。
- `required`：默认 true。当前版本所有 FAIL 都会让 `verify` 返回退出码 1；`required` 用于人读时区分阻断项与建议项。
- `check`：机器可执行检查，参数见 `02-证据类型.md`。

**验收项写作要求**：可判定、无歧义、无主观形容词。反例「代码质量良好」「看起来没问题」「已妥善处理」；正例「`src/login.py` 中不再出现 `legacy_auth`」「`REPORT.md` 汉字数 ≥ 800」。

## 结果状态机

| 状态 | 含义 | 能否当作完成 |
| --- | --- | --- |
| `PASS` | 本次复验实际执行检查并通过 | 仅表示**该检查项**通过 |
| `FAIL` | 检查执行了，但条件不成立，或产物缺失/异常 | 否 |
| `UNVERIFIED` | 未执行（如 command 未授权）、类型未知、无法判定 | **否，绝不可写成通过** |
| `STALE` | 上次通过后产物哈希变化，旧证据失效 | **否，须重新验收** |

总体结论：`FAIL` > `STALE` > `PARTIAL`（存在 UNVERIFIED）> `PASS` > `EMPTY`（无验收项）。`EMPTY` 不表示合格，表示契约尚未建立。

状态转换由 `verify` / `resume` 产生；`attest` 不改变任何状态。

## 事件日志

`events.jsonl` 每行一条 JSON：`{"at","event", ...}`。事件类型：`init`、`add`、`verify`、`attest`、`handoff`、`resume`。

`claims.jsonl` 每行：`{"at","id","note","weight":"声明，不参与验收判定"}`。两个日志都只追加，不修改、不删除——事后对照「AI 当时声称做了什么」与「实际复验结果」，是复盘最有用的数据。

## 证据指纹与漂移

`verify` 为每个基于文件的检查记录依赖产物的 SHA-256，写入 `receipt.json` 的 `results[].artifacts`。`resume` 用上一次的指纹与本次比对：

- 指纹一致 → 本次重新执行检查，仍可能 FAIL（例如文件被别处改坏），不直接继承 PASS；
- 指纹变化 → 该项标记 `STALE`，旧验收单作废；
- `command` 类型没有文件指纹，因此**不能**检测漂移，每次 `resume` 必须重新执行；未授权时保持 `UNVERIFIED`。

## 安全边界

- 所有路径为项目根内相对路径；拒绝绝对路径、盘符、`..` 逃逸、解析后越出项目根的符号链接。
- 脚本不删除、不改写用户的产物文件，只写 `TASK.md`、`RECEIPT.md`、`HANDOFF.md` 与 `.receipt/` 内文件。
- `command` 默认拒绝执行；授权后以 `shlex.split` + `shell=False` 运行，默认 60 秒超时，不支持管道与 `&&`。契约来自他人时必须逐条审阅命令。
- 不联网、不调用模型、不读取项目根以外的文件。

## 契约变更

增删验收项、放宽阈值、修改检查参数都属于契约变更：

1. 旧 `RECEIPT.md` / `receipt.json` 立即作废；
2. 重跑 `verify`；
3. 在 `TASK.md` 或提交信息中说明变更原因，不要用「提高通过率」为目的悄悄放宽。

## 版本

`format_version = 1`。后续字段变更须附旧数据夹具、迁移说明与验证步骤；迁移预览与执行分开，各自取得人的确认。
