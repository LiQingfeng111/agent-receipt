# 证据类型

所有检查都是**确定性**的：同样的文件与契约，任何时候重跑结果一致（`command` 除外，它取决于外部环境，因此必须每次重跑）。

## 总表

| 类型 | 必需参数 | 可选参数 | PASS 条件 |
| --- | --- | --- | --- |
| `file_exists` | `path` | — | 路径存在且为普通文件 |
| `file_contains` | `path` + (`text` 或 `pattern`) | `absent` | 文本/正则命中（或取反后未命中） |
| `file_hash` | `path` + `hash` | — | 文件 SHA-256 与期望一致（大小写不敏感） |
| `min_han` | `path` | `min`（默认 1） | 汉字数 ≥ min |
| `min_lines` | `path` | `min`（默认 1） | 非空行数 ≥ min |
| `json_equals` | `path` + `key` | `value` | 字段值转字符串后相等 |
| `count_files` | `pattern`（glob） | `min`（默认 1） | 匹配到的文件数 ≥ min |
| `command` | `cmd` | `contains`、`timeout` | 退出码 0，且输出含 `contains`（若给出） |

## 逐类说明与陷阱

### file_exists
最弱但最常用。`--path report.md`。只是「有文件」，不代表内容正确；建议叠加 `min_lines` 或 `file_contains`。

### file_contains
```bash
--check file_contains --path REPORT.md --text "## 结论"
--check file_contains --path REPORT.md --pattern "版本[:：]\s*v?\d+"
--check file_contains --path REPORT.md --text "待补充" --absent
```
- 检查前会移除 HTML 注释，避免模板注释造成误判。
- `--absent` 用于「不应残留占位符 / 旧接口名」，是防 AI 交半成品的最实用一项。
- `pattern` 用 Python `re` 语法；正则写错会返回 `FAIL` 并附异常信息，不会静默通过。

### file_hash
`--hash <64位sha256>`。适合冻结交付物（例如「导出的 PDF 就是这一版」）。缺点：任何正常修改都会 FAIL，适合定稿阶段而非开发过程。

### min_han
按 Unicode 汉字区间计数，排除 YAML frontmatter 与 HTML 注释，含标题文字。中文报告/稿件篇幅用这个，不要用字符数或 token 数。另报字符数时须单独标注口径。

### min_lines
只数非空行。用来识别「文件建了但是空壳」。

### json_equals
`--key a.b.c` 支持点号路径；值统一转字符串比较，所以 `1` 与 `"1"` 视为相等。适合状态文件、配置、导出清单的字段核对。

### count_files
`--pattern "out/*.md"` 或 `"out/**/*.md"`（支持 `**`）。拒绝绝对路径与 `..`。只统计普通文件。为控制验收单体积，证据指纹最多记录前 20 个匹配文件。

### command
```bash
--check command --cmd "python -m unittest discover -s tests" --contains "OK" --timeout 120
```
- **默认不执行**，返回 `UNVERIFIED`；只有 `verify --allow-commands` 才会运行。
- 以 `shlex.split` 拆词、`shell=False` 执行，不支持管道、`&&`、重定向；需要这些就写成脚本文件再调用。
- 工作目录是项目根，超时默认 60 秒。输出末 3 行会写进证据（可能被截断）。
- 命令由写契约的人负责；来自他人的契约必须逐条审阅后再授权。
- 该项没有文件指纹，`resume` 无法检测漂移，每次都必须重跑；未授权时永远保持 `UNVERIFIED`。

## 组合建议

| 场景 | 建议验收项 |
| --- | --- |
| 生成一份报告 | `file_exists` + `min_han` + `file_contains(标题)` + `file_contains(占位符, absent)` |
| 重构一个模块 | `file_contains(旧接口, absent)` + `command(测试)` + `file_hash(锁文件)` |
| 批量导出 | `count_files` + `min_lines` + `json_equals(清单字段)` |
| 定稿交付 | `file_hash` + `command(构建)` |

## 写不好验收项的三个信号

1. 检查项全都是 `file_exists` —— 只能证明「建了文件」，证明不了「做完了」。
2. 阈值随手填、比实际产物低很多 —— 通过率好看，但没有约束力。
3. 契约里没有一条 `absent` 或 `command` —— 容易放过占位符残留与真实失败。

契约要由人确认，写得太松等于没写。
